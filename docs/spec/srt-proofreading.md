# 講義字幕(SRT)の校正 — 理系講義(lecture-1〜3)の自動字幕の誤認識を直し、PO の承認後にアプリが読む字幕へ反映する

## Issue

#35

## 目的(Why)

`lectures/lecture-1/subtitles.srt` は YouTube の自動生成字幕で、音声認識の誤りが多い(例: 「day 9の表面積」「4敗ある事情」)。この字幕は、(1) 協力者が動画視聴中に読む字幕として表示する予定(FR-70)、(2) AI チューターのプロンプトの文脈(`interfaces/tutoring/srt.py`)、の2つに使われる。誤りは、学習体験と AI 応答の質の両方を損ない、協力者の脱落(プロダクトゴールの主指標「有効な1人分のデータ」)にも効く。

FR-72 は「AI が全文の修正案を作り、PO が前後の差分を確認して確定する」と定めている。スプリント 007 では lecture-1 をサンプルとして修正案と差分を作り、PO が承認した修正案をアプリが読む字幕へ反映した(修正 107 件)。

スプリント 008 では、その結果を見た PO の依頼により、残りの理系講義 lecture-2(モンティ・ホール問題)と lecture-3(3囚人問題)を、同じ手順で校正して反映する。lecture-2・3 の字幕も自動字幕で、誤認識が多い(例: lecture-2 ブロック 1「数学史上最も切ろう」、lecture-3 ブロック 1「3終人問題」)。理系3本の字幕がそろって校正済みになると、AI チューターが3人の協力者のどの講義でも、正しい字幕を文脈として使える。文系3本は、素材の準備後に扱う(今回は対象外)。

## 実現内容(What)

1. lecture-1 の自動字幕の誤字脱字・誤認識を直した**修正案**を、元のファイルとは別のファイル `lectures/lecture-1/subtitles.proofread.srt` として作る。番号、時刻、ブロックの構成は元と同じで、変わるのはテキストだけ。
   - 表記の方針: 数式は記号で書く(例: 「4πr²」)。句読点は足さない(自動字幕の区切りを保ち、範囲を誤認識の修正に限る)。
2. 修正前後の**差分一覧** `lectures/lecture-1/proofread-diff.md` を作る。PO が、これだけを読んで、各修正の妥当性と全体の傾向を判断できる。差分一覧は、次の節を持つ。
   - **修正の一覧**: 1修正 = 1行。番号、時刻、修正前、修正後、理由、確信度(高/中/低)。
   - **集計**: 修正の総件数、確信度ごとの件数、誤認識のパターン(例: 数式の読み、専門用語、同音異義)ごとの件数。
   - **PO への質問**: 確信度が低く、AI が決めなかった箇所の一覧。
   - **気づいた点(報告のみ)**: 時刻の重なりの件数など、今回は直さないもの。
3. 動画は見られないため、修正は文脈(前後の行、講義の主題)からの推定であり、その不確かさを確信度で表す。
4. **反映**: PO が差分を承認した後に、承認された修正案の内容で、アプリが読む `lectures/lecture-1/subtitles.srt` を置き換える。置き換えの後も、番号、時刻、ブロックの構成、文字コード、改行コード(CRLF)、末尾の改行の有無は元と同じで、変わるのはテキストだけ。これにより、AI チューターのプロンプトに入る講義字幕が、修正後のテキストになる。
   - PO の承認より前に、`subtitles.srt` を変更しない。
   - PO への質問に PO が回答し、修正を指示したときは、その指示を修正案と差分一覧に反映してから、承認を受けて置き換える。

以上の 1〜4 は、スプリント 007 で lecture-1 に対して行った(修正 107 件を反映)。

5. **lecture-2・3 への適用(スプリント 008)**: lecture-2 と lecture-3 のそれぞれに、1〜4 と同じことを行う。ファイルは講義ごとに `lectures/{lecture_id}/` の下に置く(`subtitles.proofread.srt`、`proofread-diff.md`、反映の対象の `subtitles.srt`)。講義ごとに異なる値(ブロック数、物理行数、最終の終了時刻、`[...]` 表記の位置、重なりの数)は、「前提」の lecture-2・3 の表に従う。
