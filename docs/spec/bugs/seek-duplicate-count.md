# バグ修正: 1回のシーク操作が、視聴ログに複数回として記録される

- 状態: **承認済み(2026-09-26。AC10 の (c)(d) 追加を含む AC1〜AC10)**(Q1〜Q5 は PO 決定済み(2026-09-26)。未決の論点なし)

## Issue

#10(前方シークや後方シークで1回シークしたつもりが記録上は複数回として記録される)

## 不具合現象と再現手順(Why)

### 発生している現象

講義動画の画面で、学習者がシークバーを1回操作して再生位置を移動すると、視聴ログに `forward_seek`(前方シーク)または `backward_seek`(後方シーク)が複数件記録される。PO の実機確認では、1回のシークで 10〜11 件、ウィンドウのリサイズ操作をしていなくても 3〜5 件記録された。記録される複数件は、すべて同じ内容(同じ到達位置、同じ移動量)である。

本システムは、視聴行動(シーク回数など)を実験データとして使い、振り返り画面(LAD)や AI チューターの文脈にも使う。記録上の回数が実際の操作回数と一致しないと、実験として成り立たない。また、LAD の操作回数や学習者プロファイルの指標が水増しされる。

「シーク」の定義(Issue の PO の言葉):

- シークとは、現在の再生位置から、シークバーで任意の位置まで移動すること。
- 移動し続けている間は数えない。
- 任意の位置で止め、操作を終えた時点で、やっと1回と数える(マウスは、離した時点。後述「POの意図」)。

### 再現手順

1. 参加者 ID 付きの URL で講義動画の画面を開き、動画の読み込みを待つ。
2. (件数が増える条件)ブラウザのウィンドウの大きさを何度か変える。変えなくても再現する(PO 実機で 3〜5 件)。
3. シークバーのつまみをマウスで押し、前方(または後方)の任意の位置までドラッグして、離す。
4. ブラウザの開発者ツールの Network で、`POST /api/viewing-log` の件数を見る。
5. 期待: `forward_seek`(または `backward_seek`)が 1 件。
   実際: 同じ内容の `forward_seek`(または `backward_seek`)が複数件(PO 実機で 10〜11 件、リサイズなしで 3〜5 件)。

## 修正内容(What)

### 根本原因

講義動画の画面で、シークバーの初期化処理(動画の準備完了時とウィンドウのリサイズのたびに呼ばれる)が、呼ばれるたびにシークの記録処理をシークバーへ追加し、既存のものを外さない。そのため、1回のシーク確定で、追加された処理の数だけ同じシーク記録が送られる。〔コードの観測(実行)と、PO の実機観測で確定〕

### 修正方針

- **シークバーの初期化(準備完了時、リサイズ時)が何回行われても、1回のシーク操作で記録されるシークは、ちょうど 1 件にする。**
- マウス: つまみを押して動かしている間は記録しない。離した時点で、開始位置から到達位置への移動を 1 件記録する。
- キーボード(矢印キー): キー操作による位置の確定ごとに 1 件記録する(現状どおり)。
- 記録の内容(種類 `forward_seek` / `backward_seek`、再生位置 = 到達位置、移動量 = 到達位置 − 開始位置)は変えない。
- 開始位置と到達位置が同じときに記録しない挙動は変えない。
- シーク以外の記録(`play` / `pause` / `forward_skip` / `backward_skip`)、シークバーの幅の追従(リサイズ時)、再生中のシークバーと時刻表示の同期は変えない。
- バックエンド(受信、保存、集計)は変えない。

### スコープ外

- **既に記録された視聴ログ(重複を含む)の補正**(PO 決定 Q3=A)。実験データとして使う場合、修正前の期間のシーク回数は水増しされている。必要なら別 Issue で扱う。
- バックエンドでの重複除去。
- **「ドラッグ中」の目印が残る場合の対処**(PO 決定 Q2=A)。**別 Issue 候補**:
  - 内容: 移動の開始時に置く「ドラッグ中」の目印(`sessionStorage`)は、確定のイベントでしか消えない。つまみを動かしてから元の位置に戻して離すなど、ブラウザが確定のイベントを発火させない操作では、目印が残る可能性がある。残ると、その後の一時停止が記録されない、次のシークの開始位置が古い値になる、などが起こりうる。
  - 確認済みのこと: 入力イベントだけを発火させると目印が残る〔確認: 実行(一時スクリプト)〕。
  - 未確認のこと: 実機のブラウザが確定のイベントを発火させない条件 `(未確認: コードを読んだ推測)`。別 Issue では、実機での再現確認を先に行う。
  - 本 PBI での扱い: この挙動を変えることを求めない(AC に含めない)。
