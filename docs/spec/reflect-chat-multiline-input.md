## Issue

#8(チャット入力欄で長文を入力しても、改行ラップやスクロールがされない)

## 目的(Why)

振り返り画面(`/reflect`)の AI チューターへの入力欄は1行の欄で、欄の幅を超える文字数を入力しても折り返されず、スクロールもされない。そのため、入力した文章の前半が見えなくなり、長文(振り返りの記述)を書きにくい。

学習者が自分の学習を言葉にして振り返ることは、このシステムの自己調整学習支援の中心である。入力欄が文章全体を見渡せる形になれば、長文の振り返りを書きやすくなり、書いた内容を送信前に読み返せる。また、学習者が段落を分けて書いた場合、その改行が送信後の表示でも保たれれば、自分が何を書いたかを会話の中で読み返しやすい。

## 実現内容(What)

対象は `/reflect` の画面の「AI チューター」のチャット入力欄と、その表示欄のユーザーメッセージ。

### 入力欄

- 入力した文章は、欄の幅で自動的に折り返して表示される。横方向にはスクロールしない。
- 何も入力していないとき、入力欄の高さは1行分。
- 入力した内容の行数(折り返しと改行を含む見た目の行数)に合わせて、入力欄の高さが伸び縮みする。
- 見た目の行数が **8行**(上限。PO 決定済み。PO確認で見た目を見て微調整する余地あり)を超えると、入力欄はそれ以上伸びず、欄の中で縦にスクロールして全体を見られる。
- Enter キーで送信する。Shift+Enter で改行を入れる(送信しない)。
- Ctrl / Cmd / Alt のいずれかを押したままの Enter では、何も起きない: 送信せず、改行も入らない(S1 で PO 決定済み)。
- Enter は、どの場合も(送信する場合、空・空白だけで送信しない場合、送信中、修飾キー付きの場合)入力に改行を加えない。改行を入れる手段は Shift+Enter だけ(S2 で PO 決定済み)。
- 日本語入力(IME)の変換中の Enter は、変換の確定に使われ、送信しない(対象ブラウザ: Chrome と Safari)。
- 送信ボタンによる送信は従来どおり使える。

### 送信

- 送信する内容の整形は、現状を維持する: 前後の空白・改行を取り除き、途中の改行や連続する空行はそのまま送る。(Q2 で PO 決定済み)
- 空、または空白・改行だけの入力は、Enter でも送信ボタンでも送信しない(現状を維持)。このとき Enter を押しても、入力に改行は加わらず、入力欄の内容は変わらない(S2 で PO 決定済み)。
- 送信すると、入力欄は空になり、高さは1行分に戻る。
- 送信中(AI チューターの応答を待っている間)は、Enter でも送信ボタンでも、次の送信は行われない(現状の二重送信防止を維持)。このとき Enter を押しても、入力に改行は加わらない(Q3 で PO 決定済み)。

### 表示欄

- 送信したユーザーメッセージは、送信した内容の改行(連続する空行を含む)を保って表示される。
- 送信したユーザーメッセージに、空白を含まない長い文字列(URL や半角英数字の連続など)があっても、メッセージの吹き出しの幅で折り返され、吹き出しや表示欄の外へはみ出さない。
- ユーザーの入力は、HTML として解釈されず、入力した文字のとおりに表示される(現状を維持)。

## 受入基準

前提(すべての AC に共通): `/reflect?participant_id=<有効なID>` を開いた状態。「行」は、入力欄に見えている行(折り返しと改行の両方を含む)を指す。

1. **折り返し**: 入力欄の幅を超える文章(日本語の文章、および空白を含まない半角英数字の長い文字列の両方)を入力すると、欄の幅で折り返して表示され、横スクロールバーが出ず、入力した文字がすべて欄の中に見えている(8行以内の場合)。〔検証: PO確認〕
2. **初期の高さ**: 画面を開いた直後、入力が空の入力欄の高さは1行分で、placeholder「メッセージを入力...」が表示されている。〔検証: PO確認〕
3. **自動で伸びる・縮む**: 1行から入力を増やして2行、3行…8行になるにつれて、入力欄の高さが1行ずつ伸び、縦スクロールバーは出ない。また、文字を消して行数が減ると、入力欄の高さも行数に合わせて縮む。〔検証: PO確認〕
4. **上限とスクロール**: 9行以上を入力すると、入力欄の高さは8行分で止まり、欄の中で縦にスクロールして、先頭行から最終行まで見られる。入力中の位置(カーソル)は欄の中に見えている。〔検証: PO確認〕
5. **Enter で送信**: 空白以外の文字を含む入力で、IME の変換中でないときに Enter(修飾キーなし)を押すと、メッセージが1件送信され、Enter による改行は入力にも送信内容にも加わらない。〔検証: 自動テスト(キー操作の論理)+ PO確認(実ブラウザ)〕
6. **Shift+Enter で改行**: Shift+Enter を押すと、カーソル位置に改行が1つ入り、送信は行われない(`POST /chat` が0件)。〔検証: 自動テスト(送信されないこと)+ PO確認(改行が入ること)〕
7. **IME の確定の Enter で送信しない**: 日本語入力で「きょう」と入力し、変換中に Enter を押して「今日」を確定したとき、送信は行われず(`POST /chat` が0件)、入力欄に「今日」が残る。確定後にもう一度 Enter を押すと送信される。対象ブラウザは Chrome と Safari(Q1 で PO 決定済み)。〔検証: 自動テスト(変換中の Enter で送信しない論理)+ PO確認(実IMEで、Chrome と Safari のそれぞれ)〕
8. **空・空白だけは送信しない**: 入力が空、または空白・改行だけ(例: Shift+Enter で改行だけを3つ入れた状態)のとき、Enter を押しても、送信ボタンを押しても、送信は行われず(`POST /chat` が0件)、表示欄にユーザーメッセージが追加されない。また、このときの Enter で入力に改行は加わらず、入力欄の内容は Enter を押す前と同じ(空のときは空のまま、空白・改行だけのときはその内容のまま)。(改行に関する部分は S2 の PO 決定の反映)〔検証: 自動テスト〕
9. **送信内容の整形(現状維持)**: 入力が「(空白2つ)1行目(改行)(改行)(改行)2行目(改行)(空白2つ)」のとき、送信される内容は「1行目(改行)(改行)(改行)2行目」(前後の空白・改行を除き、途中の改行3つはそのまま)。Enter で送っても送信ボタンで送っても同じ。(Q2 で PO 決定済み)〔検証: 自動テスト〕
10. **送信後の入力欄**: 5行分の入力を送信すると、入力欄は空になり、高さは1行分に戻る。〔検証: 自動テスト(入力欄が空になること)+ PO確認(高さが1行分に戻ること)〕
11. **送信中の二重送信防止(維持)**: 送信して AI チューターの応答を待っている間に、次の入力を書いて Enter を押しても、送信ボタンを押しても、送信は行われない(`POST /chat` は最初の1件だけ)。このとき、Enter で入力に改行が加わらず、書いた入力はそのまま残る(Q3 で PO 決定済み)。応答(成功・エラーのどちらでも)を受け取った後は、Enter で送信できる。〔検証: 自動テスト〕
12. **表示で改行を保つ**: 「1行目(改行)2行目(改行)(改行)4行目」を送信すると、表示欄のユーザーメッセージが4行(3行目は空行)として表示される。〔検証: 自動テスト(表示要素の文字列に改行が保たれていること)+ PO確認(見た目で改行・空行が表示されること)〕
13. **HTML として解釈しない(維持)**: `<b>太字</b>` および `<img src=x onerror=alert(1)>` を送信すると、表示欄にはその文字列が文字どおり表示され、太字にならず、画像の要素が作られず、スクリプトも実行されない。改行を含む場合(例: 「`<b>`(改行)`x`」)も同じ。〔検証: 自動テスト(表示要素に HTML として挿入されないこと)〕
14. **送信ボタンの送信(維持)**: 複数行の入力を送信ボタンで送信すると、AC9 と同じ内容が送信され、AC10・AC12 と同じ結果になる。〔検証: 自動テスト〕
