# 講義の選択 — 研究協力者が、登録された講義から学習する講義を1回選び、その講義で一貫して学習できる

## Issue

#34(関連要件: FR-60、FR-62、FR-63、FR-05(置き換え)。関連: FR-52、NFR-12、NFR-15、NFR-16。依存: #30(ログイン、完了)、#33(文系 lecture-4〜6 の登録、完了。develop に取り込み済み))

## 目的(Why)

研究協力者は、理系レベル3本・文系レベル3本の計6本から、自分に合った講義を自分で選んで学習する。自分に合わない内容を割り当てられると、視聴・小テスト・AI 対話の途中で脱落しやすい。脱落が減れば、「有効な1人分のデータ」に達する協力者が増え、プロダクトゴール(有効10人以上を検証できる状態にする)に近づく。

また、選んだ講義と、記録される学習データの講義が食い違うと、LAD・AI チューターの文脈・対話ログが別の講義のものになり、研究データとして使えない。そこで、選んだ講義で、視聴・小テスト・LAD・AI 対話・対話ログが一貫して動くようにし、`participant_id` による講義の固定対応(FR-05)をなくす。

## 実現内容(What)

### 1. 選択肢

- 選択肢は、**講義カタログに登録された講義すべて**とする。#33 の完了後は、lecture-1〜6 の6本になる。本 PBI は、講義の登録(動画・小テスト・講義情報・字幕)を行わず、#33 の成果物に依存する。
- 各選択肢に、講義の題名と系統(「理系」または「文系」)を表示する。題名と系統は講義カタログのものを使う。講義は、系統の項目を持つ(新設。値は「理系」「文系」の2つ。各講義の値の登録は #33 との調整事項。「制約・関連機能」を参照)。
- 並び順は、カタログの順(lecture-1〜6。理系3本の後に文系3本)とする。
- 同じ講義を選べる人数に上限を設けない。系統ごとの人数の釣り合いを取る仕組みは設けない。

### 2. 選択の画面と導線

- ログインした協力者が、まだ講義を選んでいないとき、参加者の画面(`/lecture`、`/reflect`、`/`)を開くと、選択の画面へ移る(HTTP 302)。ログイン後の移動先が `/reflect` だったときも、未選択なら選択の画面へ移る。
- 選択の画面で講義を1つ選ぶと、まだ保存されず、選んだ講義の題名と、「一度選ぶと変更できない」ことと、確定の操作が表示される。確定の操作をすると、選択が保存され、講義の画面へ移り(HTTP 302)、選んだ講義の動画・字幕・小テストが表示される。確定せずに戻れば、別の講義を選び直せる。
- 選択済みの協力者が、ログイン・`/`・`/lecture` を開くと、選択の画面を経ずに、選んだ講義の画面が表示される。選択済みの協力者が選択の画面を開いたときは、講義の画面へ移る(HTTP 302)。
- 選択の画面と選択の確定は、ログインが必要(FR-51)。協力者はログインした ID で決まり(FR-52)、本人の選択だけを保存する。
- 選択の確定に、カタログにない講義 ID、空の値が送られたとき、または講義 ID が送られないときは、HTTP 400 で拒否し、何も保存しない。

### 3. 選択の保存と固定(FR-63)

- 選択は、その協力者とその講義の学習セッションとして保存される。選択の確定のときに、`(協力者, 講義)` の学習セッションが1つでき、視聴・小テスト・対話の記録はまだない。学習セッションの開始時刻は、選択を確定した時刻になる。
- 協力者の学習セッションが、その協力者の選択を表す。協力者ごとに学習セッションは1つだけで、本 PBI の後のアプリは、選択した講義以外の学習セッションを作らない(講義は選択で決まり、異なる `lecture_id` は 403 で拒否するため)。
- 選択は、一度保存されたら、協力者の操作では変わらない。ログアウト・再ログイン・別のブラウザ・ログインの有効期限(12時間)の経過の後も、同じ講義になる。
- 選択済みの協力者が、別の講義の選択の確定を送っても(例: 2つのタブ、送信の二重化)、保存された選択は変わらず、学習セッションも増えず、最初に保存された講義の画面へ移る。
- **アプリには、選択を変える機能がない**(協力者向けにも研究者向けにもない)。協力者が選び間違えたときは、研究者が作成スクリプトで新しい ID を払い出し、元の ID を停止する(#30 の手順)。新しい ID で、改めて講義を選ぶ。この手順を README に書く。

### 4. 講義 ID の一貫(FR-62)

- 参加者の画面と API は、**保存された選択**を、その協力者の講義とする。`participant_id` の固定マップと既定の講義(`DEFAULT_LECTURE_ID`)は、参加者の要求の講義の決定に使わない。
- 次のすべてが、選んだ講義で動く。
  - 講義の画面(動画・字幕・小テストの表示)
  - 視聴ログ(`POST /api/viewing-log`)、小テスト(`POST /api/quiz-attempts`)の記録
  - LAD(`GET /api/participants/<id>/lad`)、最終更新時刻(`GET /api/last-updated`)。選択の直後で記録がないときは、200 で、視聴・小テストが空のデータと「最終更新なし」を返す
  - AI 対話(`POST /chat`。AI に渡す講義の文脈(字幕・講義情報)と、学習データ(LAD)を含む)
  - 対話ログの保存(`POST /api/dialog-log`。終了ボタン・ページ離脱の両方)と、研究者のダウンロードに出る講義 ID
- **API の `lecture_id`(本文・クエリ)**: 対象は上の API のすべて。
  - 値の形は、#30 の `participant_id` の規則に合わせる。ただし、空文字は #30 と異なり、HTTP 400 で拒否し、記録しない(本文・クエリとも。現状の扱いの維持。DR-003)。本文の `null` は「送られていない」と同じに扱う。数値は10進の文字列にしてから比べる(真偽値は数値に含めない)。文字列・数値・`null` 以外(真偽値、配列、オブジェクト)のときは、HTTP 400 で拒否し、記録しない。
  - 送られていない、または選択した講義と一致するときは、選択した講義で処理する。
  - 選択した講義と異なるとき(カタログにある別の講義、カタログにない値)は、HTTP 403 で拒否し、2つの DB のどこにも記録しない。`POST /chat` では AI を呼ばない。
- **未選択の協力者の API**: 上の API のすべてを、`lecture_id` の値によらず HTTP 409 で拒否し、2つの DB のどこにも記録しない。`POST /chat` では AI を呼ばない。LAD・最終更新も 409 とする。
- **検査の順序**(参加者の API。先の検査で拒否したら、後の検査は行わない)(DR-004):
  1. 未ログインの拒否(401)と、他人の `participant_id` の拒否(403)(#30)
  2. 未選択の拒否(409)。`lecture_id` の値(空文字、真偽値、カタログにない値を含む)によらない
  3. `lecture_id` の値の形の拒否(400)。空文字、真偽値、配列、オブジェクト
  4. 選択との不一致の拒否(403)。カタログにある別の講義と、カタログにない値のどちらも。参加者の API は、講義がカタログにないことを理由とする 404(`LECTURE_NOT_FOUND`)を返さない
  5. 既存の検査(他人の対話セッション、存在しない対話セッションの 404 など。#30 のとおり変えない)
- **`/lecture?lecture_id=`**: 選択済みの協力者が、選択と異なる値(カタログにある別の講義、カタログにない値)を付けて開くと、指定を無視し、200 で選択した講義の画面を表示する。空の値(`lecture_id=`)を付けて開くと、404 になる(現状の扱いの維持。DR-003)。未選択の協力者が値(空の値を含む)を付けて開くと、指定を無視して選択の画面へ移る(HTTP 302)。URL の指定では選択を確定させない。
- **`/reflect?lecture_id=`**(DR-001): 選択済みの協力者が、指定なし、または選択と一致する値で開くと、200 で、ページに選択した講義の講義 ID が埋め込まれる。選択と異なる値(カタログにある別の講義、カタログにない値のどちらも)を付けて開くと、HTTP 403 で拒否する。空の値を付けて開くと、404 になる(現状の扱いの維持。DR-003)。未選択の協力者が開くと、値(空の値を含む)によらず、選択の画面へ移る(HTTP 302)。URL の指定では選択を確定させない。
  - 結果として、選択済みの協力者の講義画面と振り返り画面に埋め込まれる講義 ID は、常に選択した講義になり、画面が API に付けて送る `lecture_id` は選択した講義になる。
  - 画面の検査の順序は、API と同じく、未ログイン(#30 のとおりログイン画面へ 302)→ 未選択(選択の画面へ 302)→ 値の検査(空の値の 404、`/reflect` の不一致の 403)とする。

### 5. 既存のデータの消去(運用手順)

- 本 PBI の前に記録されたデータは、テスト用だけである。本 PBI のリリースの前に、研究者が、2つの DB(`learning.db`、`tutor.db`)の学習データ・対話データを、本番の複製(#29 の GCS)を含めて消去する。消去の後は、全員が未選択から始まる。
- アプリには、既存のデータを選択済みと判定する処理、移し替える処理、消去する処理を設けない。消去の後に学習セッションが2つ以上ある協力者は生じない前提とし、その扱いは定めない。

## 受入基準

テストの講義: 選択肢は「カタログに登録された講義」であるため、自動テストは、テスト時点のカタログの全講義(#33 の完了後は lecture-1〜6)について繰り返す。少なくとも、`lecture-1` 以外の講義(例: lecture-2、#33 の完了後は lecture-5)を必ず含める(固定マップ・既定の講義との区別のため)。「2つの DB」は `learning.db` と `tutor.db`。

### A. 選択の画面と導線

1. **未選択の導線**: 選択のない ID でログインし、`/`、`/lecture`、`/reflect`、`/reflect?lecture_id=lecture-2`、`/reflect?lecture_id=lecture-9`(カタログにない値)を開くと、5つとも HTTP 302 で、移動先が選択の画面であり、選択は保存されない(`learning_sessions` の行数は変わらない)。ログインの移動先に `/reflect` を指定してログインしたときも、移動先は選択の画面になる。〔検証: 自動テスト〕
2. **選択肢の表示**: 選択の画面は 200 で、講義カタログに登録された講義が、カタログの件数と同じ数だけ、カタログの順に、各講義の題名と系統(「理系」または「文系」)つきで並ぶ。カタログにない講義は並ばない。〔検証: 自動テスト〕
3. **確定の前の確認**: 選択の画面で講義 X を選ぶ最初の操作をすると、応答に X の題名と「一度選ぶと変更できない」旨の文言と確定の操作が含まれ、この時点では選択は保存されない(`learning_sessions` の行数は変わらず、続く `/lecture` は選択の画面への 302 のまま)。〔検証: 自動テスト〕
4. **選択の確定**: AC3 に続けて確定の操作をすると、講義の画面へ移り(HTTP 302)、`learning_sessions` に `(その ID, X)` の行が1つでき、視聴・小テストの記録はない。続く `/lecture` は 200 で、画面の講義 ID が X、動画が X の動画、小テストが X の小テストである。〔検証: 自動テスト(カタログの全講義で繰り返す)〕
5. **カタログにない講義の拒否**: カタログにない講義 ID(例: `lecture-9`)、空の値、講義 ID なしで選択の確定を送ると、HTTP 400 で、選択は保存されない(続く `/lecture` は選択の画面への 302 のまま)。2つの DB の行数は変わらない。〔検証: 自動テスト〕
6. **選択済みの導線**: 講義 X を選んだ ID で、ログアウトして再びログインすると、ログイン後に選択の画面を経ず、`/lecture` が 200 で X の画面になる。別のテストクライアント(別のブラウザに相当)でログインしても同じである。選択済みで選択の画面を開くと、HTTP 302 で講義の画面へ移る。〔検証: 自動テスト〕
7. **画面の操作**: ブラウザでログインし、選択の画面に #33 の完了後の6本が、題名と系統つきで、理系3本の後に文系3本の順に並ぶこと、題名と系統から講義を区別できること、1本を選ぶと「一度選ぶと変更できない」ことが表示され、確定せずに戻って選び直せること、確定すると、その講義の動画・字幕・小テストの画面になること。〔検証: PO確認〕

### B. 選択の固定(FR-63)

8. **固定**: 講義 X を選んだ ID で、別の講義 Y の選択の確定を送ると、選択は X のまま変わらず、HTTP 302 で講義の画面へ移り、続く `/lecture` は X の画面である。その ID の `learning_sessions` の行は `(その ID, X)` の1つのままである。ログインの有効期限(12時間)を過ぎて再ログインした後も X である。〔検証: 自動テスト(時刻を進める)〕
9. **協力者ごとの独立**: ID `A` が X を、ID `B` が Y を選ぶと、`A` の画面と記録は X、`B` の画面と記録は Y で、互いの選択に影響しない。同じ講義を複数の ID が選べる。〔検証: 自動テスト〕

### C. 講義 ID の一貫(FR-62)

10. **学習データの記録**: 講義 X を選んだ ID で、本文に `lecture_id` を含めない形と、画面が送る形(本文の `lecture_id` に X を付けた形)のそれぞれで、`POST /api/viewing-log` と `POST /api/quiz-attempts` を送ると、どちらの形でも2つとも成功し、記録は選択の確定でできた `(その ID, X)` の学習セッションに入る。その ID の学習セッションは1つのままである。〔検証: 自動テスト(カタログの全講義で繰り返す)〕
11. **LAD と最終更新**: 講義 X を選んだ ID で、記録がない状態で `lecture_id` を付けずに `GET /api/participants/<ID>/lad` と `GET /api/last-updated` を呼ぶと、2つとも 200 で、LAD の視聴・小テストは空、最終更新は「なし」を示す値である。AC10 の後に同じく呼ぶと、X の学習セッションの視聴・小テストと最終更新時刻が返る。〔検証: 自動テスト〕
12. **AI 対話**: 講義 X を選んだ ID で、本文に `lecture_id` を含めない形と、画面が送る形(本文の `lecture_id` に X を付けた形)のそれぞれで `POST /chat` を送ると、どちらの形でも、対話セッションは `(その ID, X)` の学習セッションに紐づき、AI(偽物)に渡す内容に X の講義の文脈(字幕または講義情報)が含まれ、X 以外の講義の文脈が含まれない。〔検証: 自動テスト(LLM は偽物に差し替え、渡された内容を観察する)〕
13. **対話ログ**: AC12 に続けて、`POST /api/dialog-log` を、本文に `lecture_id` を含めない形と、画面が送る形(本文の `lecture_id` に X を付けた形)のそれぞれで、終了ボタン(`end_button`)とページ離脱(`page_leave`)のそれぞれについて送ると、どの組み合わせでも、保存された対話ログの講義 ID が X で、保存された対話セッションが AC12 の(同じ形で作った)対話セッションである。研究者のダウンロード(`/research/participants/<ID>/dialog-logs`)に出る講義 ID も X である。〔検証: 自動テスト〕
14. **API の `lecture_id`**: 講義 X を選んだ ID で、`POST /api/viewing-log`、`POST /api/quiz-attempts`、`POST /chat`、`POST /api/dialog-log`、`GET /api/participants/<ID>/lad`、`GET /api/last-updated` のそれぞれについて、次のとおりになる。〔検証: 自動テスト(LLM は偽物に差し替える)〕
    - `lecture_id` を X にして呼ぶと、送らないときと同じ結果になる。本文で送る4つの API は、本文の `lecture_id` を `null` にしたときも、送らないときと同じ結果になる。
    - `lecture_id` をカタログにある別の講義、カタログにない値(例: `lecture-9`)、数値(例: `2`)にして呼ぶと、HTTP 403 で、2つの DB の行数は変わらず、`POST /chat` では AI(偽物)が呼ばれない。
    - `lecture_id` を空文字にして呼ぶと(本文で送る4つの API は本文の `""`、LAD・最終更新はクエリの `lecture_id=`)、HTTP 400 で、2つの DB の行数は変わらず、`POST /chat` では AI(偽物)が呼ばれない。
    - `lecture_id` を真偽値・配列・オブジェクトにして本文で送ると、HTTP 400 で、2つの DB の行数は変わらない。
15. **画面の `lecture_id`(`/lecture`、`/reflect`)**: 〔検証: 自動テスト〕
    - 講義 X を選んだ ID で、`/lecture?lecture_id=` をカタログにある別の講義、カタログにない値(例: `lecture-9`)にして開くと、200 で X の画面が表示される。
    - 講義 X を選んだ ID で、`/reflect` と `/reflect?lecture_id=X` を開くと、200 で、ページに埋め込まれた講義 ID が X である。`/reflect?lecture_id=` をカタログにある別の講義、カタログにない値(例: `lecture-9`)にして開くと、HTTP 403 である。
    - 講義 X を選んだ ID で、`/lecture?lecture_id=` と `/reflect?lecture_id=`(空の値)を開くと、2つとも HTTP 404 である。
    - 選択のない ID で、`/lecture?lecture_id=lecture-2`、`/lecture?lecture_id=`(空の値)、`/reflect?lecture_id=`(空の値)を開くと、3つとも HTTP 302 で選択の画面へ移り、選択は保存されない(続く `/lecture` も選択の画面への 302)。(`/reflect` に値を付けた場合は AC1)
16. **固定対応の廃止**: ID `1`、`2`、`3`、`P01`、`P30` のそれぞれで、選択をせずにログインすると、5つとも AC1 のとおり選択の画面へ移り、lecture-1/2/3 の画面は表示されない。ID `2` で講義 X(lecture-2 以外)を選ぶと、画面と記録は X になる。環境変数 `DEFAULT_LECTURE_ID` に lecture-1 以外の講義を設定しても、AC1・4・10 の結果は変わらない。〔検証: 自動テスト〕
17. **未選択の API**: 選択のない ID で、AC14 の6つの API を、`lecture_id` なし、カタログの講義の `lecture_id` 付きのそれぞれで呼ぶと、すべて HTTP 409 で、2つの DB の行数は変わらず、`POST /chat` では AI(偽物)が呼ばれない。未ログインの呼び出しは #30 のとおり 401、他人の `participant_id` は #30 のとおり 403 である(409 にならない)。〔検証: 自動テスト(LLM は偽物に差し替える)〕
18. **一通りの操作**: ブラウザで、文系の講義(#33 の完了後の lecture-4〜6 のいずれか)と、lecture-1 以外の理系の講義を、それぞれ別の ID で選び、講義の画面 → 小テスト → 振り返り画面(LAD の表示、AI との対話、終了ボタンによる対話ログの保存)を一通り使うと、どの画面でも選んだ講義の内容(動画、小テスト、LAD の記録、AI の応答の文脈)になる。研究者のダウンロードで、その対話ログの講義 ID が選んだ講義である。〔検証: PO確認〕

DR-003 の決定((b) 現状の 404・400 の維持)を、AC14・15 と矛盾なく書くために、次を補った。PO の確認を求める。

- (1) **AC14 の空文字の扱いの変更**: PO 承認済み(2026-10-26、Q2(c)・AC14)の「空文字と `null` は送らないときと同じ」のうち、空文字を「HTTP 400」に移した。`null` は「送らないときと同じ」のまま残した(現状も同じ。2026-10-28 に実行で確認)。これにより、`lecture_id` の値の形は、空文字について #30 の `participant_id` の規則と異なる。

- (3) **未選択で空の値を付けたとき**: 現状の 404 は、選択の仕組みがない時点の挙動である。未選択の協力者が `/lecture?lecture_id=`・`/reflect?lecture_id=` を開いたときは、検査の順序(未選択を値の検査より先に行う。DR-004 と同じ考え方)に合わせて、選択の画面への 302 とした(AC15)。API は、承認済みの順序のとおり 409 になる(AC17 の「値によらず 409」の範囲。AC17 の文言は変えていない)。代わりの案: 未選択でも空の値は 404(現状の文字どおりの維持)。
- (4) **AC14 の `null` の対象**: クエリには `null` を表す値がないため、`null` の確認を本文で送る4つの API に限った(承認済みの AC14 は6つの API で `null` を挙げていた)。
