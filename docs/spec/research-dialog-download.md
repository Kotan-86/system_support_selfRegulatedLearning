## 目的(Why)

LLM チューターとの対話ログは、本研究の分析対象である(プロダクトゴール: 研究協力者を通じて効果を検証できる状態にする)。Issue #11 で対話は `tutor.db` に保存されるようになったが、研究者がそれを取り出す手段がない。研究者が対話を取得できなければ、分析に進めない。専用の管理画面は作らず、URL を開くだけで取得できるようにする。

一方、対話の本文は研究協力者の発言そのものであり、研究者以外(未認証の第三者や、参加者本人)が取得できてはならない。

## 実現内容(What)

- **研究者だけが使える2つのダウンロード**を用意する。どちらも、研究者の資格情報(Basic 認証)を付けた要求にだけ応じる。
  - **参加者別**: URL のパスで参加者IDを指定すると、その参加者の対話セッションのリストが JSON で返る。
  - **全参加者一括**: すべての参加者の対話セッションのリストが、1つの JSON で返る。
- ブラウザで URL を開き、ブラウザ標準の資格情報の入力欄に入力すれば、管理画面なしで取得できる。curl 等からも同じ URL で取得できる。
- 資格情報がない・誤っている要求は拒否し、対話の内容を一切返さない。サーバーに資格情報が設定されていなければ、常に拒否する。参加者の画面と API は、これまでどおり認証なしで使える。
- 対象データがなければ、空のリスト `[]` を状態 200 で返す。
- 応答はキャッシュさせない。ダウンロードの処理は、本文をサーバーのログに出さず、DB に何も書かない(取得の記録を残さない)。

### URL と資格情報(共有IF。固定済み、2026-10-19)

| ダウンロード | 要求 | 成功時の応答 |
|---|---|---|
| 参加者別 | `GET /research/participants/<参加者ID>/dialog-logs` | 状態 200、JSON(対話セッションのリスト) |
| 全参加者一括 | `GET /research/dialog-logs` | 状態 200、JSON(対話セッションのリスト) |

- 資格情報は HTTP の Basic 認証で渡す。資格情報がない・誤っている・サーバーに未設定のときは、状態 401 で、ブラウザが入力欄を出すための認証要求のヘッダを付け、本文に対話の内容を含めない。未設定も 401 にし、設定の有無を外から区別できないようにする。
- 「サーバーに未設定」は、ユーザー名とパスワードのどちらかが設定されていない(空文字を含む)状態を指す。
- 環境変数の名前は `RESEARCHER_BASIC_AUTH_USER`(ユーザー名)/ `RESEARCHER_BASIC_AUTH_PASSWORD`(パスワード)。README の環境変数の表に書いてある。

### JSON の形(共有IF。固定済み、2026-10-19)〔決定: Q1、Q2、Q3、Q5〕

参加者別・一括とも、トップレベルは**対話セッションのリスト**。1要素 = 1つの対話セッション。**各要素の形は、dialog-log-save.md「対話ログの JSON(1件の対話ログ)」と同じ**(同じキー、同じ値の規則)。違いは、終了の保存をしていない対話セッションも含めることと、そのとき `ended_at`・`end_method` が `null` になることだけ〔決定: Q2〕。

```json
[
  {
    "format_version": 1,
    "participant_id": "1",
    "lecture_id": "lecture-1",
    "learning_session_id": "<学習セッションID>",
    "tutor_session_id": "<対話セッションID>",
    "ended_at": "2026-09-29T01:05:00+00:00",
    "end_method": "end_button",
    "messages": [
      { "role": "user", "content": "<本文>", "timestamp": "2026-09-29T01:00:00+00:00" },
      {
        "role": "assistant",
        "content": "<本文>",
        "timestamp": "2026-09-29T01:00:07+00:00",
        "utterance_type": "FACT_REQUEST",
        "dialogue_move": "ELICIT_REASON",
        "interpretation_state": { "task_understanding": { "status": "unknown", "note": "" } }
      }
    ]
  }
]
```

(`interpretation_state` は例を省略した。実際は dialog-log-save.md のとおり8つの軸を持つ。)

| キー | 値 |
|---|---|
| `format_version` | 整数 `1`(dialog-log-save.md と同じ) |
| `participant_id` | 研究用参加者ID。画面の URL で使う `participant_id` と同じ値〔決定: Q5〕 |
| `lecture_id` | 講義ID |
| `learning_session_id` | 学習セッションID(その対話セッションに対応する `learning.db` の学習セッションのID) |
| `tutor_session_id` | 対話セッションID(`tutor.db` の対話セッションのID) |
| `ended_at` | その対話セッションの `dialog_logs` の行の終了時刻(時刻の形式は dialog-log-save.md の「時刻の形式」)。`dialog_logs` に行がなければ `null` |
| `end_method` | その対話セッションの `dialog_logs` の行の終了の方法(`"end_button"` または `"page_leave"`)。`dialog_logs` に行がなければ `null` |
| `messages` | 発言のリスト。時系列(`messages` の読み出しの順。受け付けた時刻の昇順、同じなら保存された順)。終了の保存の後に追加された発言も含む。発言0件なら `[]` |
| `messages[].role` | `"user"`(ユーザ)または `"assistant"`(AI) |
| `messages[].content` | 本文。加工しない |
| `messages[].timestamp` | 時刻の文字列。ユーザーの発言は受け付けた時刻、AI の応答は生成を終えた時刻で、記録がなければ `null`(dialog-log-save.md の N3 と同じ規則) |
| `messages[].utterance_type`、`dialogue_move`、`interpretation_state` | チューターの内部判断。`assistant` の発言だけに置き、`user` の発言にはキー自体を置かない。値の規則(記録がなければ `null`、`interpretation_state` はオブジェクト)は dialog-log-save.md と同じ〔決定: Q2〕 |

- 対象: `tutor.db` の `messages` を元にし、各参加者のすべての対話セッション(終了の保存の有無を問わない。発言0件の対話セッションを含む)を含める〔決定: Q1〕。`dialog_logs` は終了の情報を添えるためだけに読み、その `log_json`(保存時点の内容)は使わない。
- 並び順: 参加者IDの昇順、同じ参加者の中では対話セッションの作成時刻の昇順、同じなら対話セッションIDの昇順〔決定: Q3〕。参加者IDの昇順は**文字列としての順**(文字コードの順)で、数値としての順ではない(例: `"10"` は `"2"` より前、`"2"` は `"foo"` より前)。
- 参加者別の参加者ID〔決定: Q6〕: URL のパスの参加者IDを、変換せず(前後の空白の除去や大文字・小文字の同一視をせず)そのまま使い、`participant_id` が完全に一致する対話セッションだけを返す。形式の検査はせず、一致がなければ `[]`(R7)。空の参加者IDは参加者別の URL で指定できない(一括には含まれる)。

## 受入基準(PO 承認済み、2026-10-19)

前提(すべての AC に共通): 「研究者の資格情報」は、サーバーの環境変数に設定した Basic 認証のユーザー名とパスワード。自動テストは、一時ディレクトリの DB と Flask のテストクライアントで行う。「両方のダウンロード」は、参加者別と一括。

1. **R1 資格情報なし・誤りは拒否**: 両方のダウンロードについて、資格情報なし、またはユーザー名かパスワードが誤った要求には、状態 401 が返り、Basic 認証の要求のヘッダ(`WWW-Authenticate`)があり、本文に対話の本文・参加者ID・対話セッションIDのいずれも含まれない。〔検証: 自動テスト〕
2. **R2 参加者本人は取得できない**: 参加者が持つ情報(自分の `participant_id` を URL のクエリや要求の本文に入れたもの)だけを付けた要求は、その参加者自身の対話であっても R1 と同じく拒否される。〔検証: 自動テスト〕〔決定: Q4〕
3. **R3 未設定なら常に拒否**: ユーザー名とパスワードのどちらか(または両方)が未設定・空文字の状態で起動すると、どの資格情報を付けた要求(空のユーザー名・空のパスワードを含む)も状態 401 で拒否される。そのときも `/chat` と `/reflect` は、これまでどおり状態 200 を返す。〔検証: 自動テスト〕
4. **R4 参加者別の内容**: 参加者 `1` が2往復の対話をし、参加者 `2` も対話をした後に、研究者が `GET /research/participants/1/dialog-logs` を要求すると、状態 200 で JSON のリストが返る。リストの各要素は参加者 `1` の対話セッションだけで、`format_version` が `1`、`participant_id` が `1`、`tutor_session_id`・`lecture_id`・`learning_session_id` が DB の値と一致し、`messages` に4件の発言が `user`・`assistant`・`user`・`assistant` の順で、送受信した本文のとおり(加工されず)、`timestamp` 付きで入っている。`assistant` の2件は `utterance_type`・`dialogue_move`・`interpretation_state` の値が `messages` の表の値と一致し(`interpretation_state` は表の値を JSON として解釈したものと等しい)、`user` の2件にはこの3つのキーがない。参加者 `2` の発言は含まれない。〔検証: 自動テスト〕〔決定: Q1、Q2、Q5〕
5. **R5 複数の対話セッションと終了の情報**: 参加者 `2` が2つの対話セッション(`lecture-2` と `lecture-3`)を持ち、片方(`lecture-2`)だけ終了の保存をしたとき、参加者別のリストに2つの対話セッションがどちらも1要素ずつ入る。保存した側の `ended_at`・`end_method` は `dialog_logs` のその対話セッションの行の値と一致し、保存していない側はどちらも `null` である。保存の後に発言を追加した場合も、保存した側の `messages` に追加した発言が含まれる。発言0件で終了の保存をした参加者 `3` の参加者別のリストには、`messages` が `[]` の要素が1つ入る。〔検証: 自動テスト〕〔決定: Q1、Q2〕
6. **R6 一括の内容と並び順**: 参加者 `1`・`2`・`foo` が対話をした後に、研究者が `GET /research/dialog-logs` を要求すると、状態 200 で1つの JSON のリストが返る。リストは、各参加者を参加者別で取得したリストの要素をすべて含み、それ以外の要素を含まない。各要素の `participant_id` と `tutor_session_id` の組は互いに異なる。並びは、参加者IDの昇順、同じ参加者の中では対話セッションの作成時刻の昇順(同じなら対話セッションIDの昇順)である。参加者IDの昇順は文字列としての順で、参加者 `10` も対話をした場合、並びは `1`、`10`、`2`、`foo` の順になる。作成時刻が同じ秒の対話セッションを含む場合も、この並びになる。〔検証: 自動テスト〕〔決定: Q1、Q3〕
7. **R7 0件は空のリスト**: 対話データのない参加者ID(存在しないIDを含む)の参加者別、および対話データが1件もない状態での一括は、状態 200 で `[]` を返す。〔検証: 自動テスト〕
   - 〔決定: Q6〕参加者IDはそのまま照合する: 参加者 `1` が対話をした後、参加者IDを ` 1`(前に空白)または `%20`(空白だけ)として参加者別を要求すると、どちらも状態 200 で `[]` が返り、参加者 `1` の対話は含まれない。〔検証: 自動テスト〕
8. **R8 キャッシュさせない**: 両方のダウンロードの、成功時(200)と拒否時(401)の応答に `Cache-Control: no-store` がある。〔検証: 自動テスト〕

### 既知の限界

- 消えない保存基盤ができるまでは、再デプロイ・再起動の前のデータは取得できない。Cloud Run で複数のインスタンスが動くと、要求を受けたインスタンスのデータだけが返る(後半は `(未確認: 実環境で未確認)`)。
- `/` を含む参加者ID、および空の参加者IDは、参加者別の URL で指定できない(一括には含まれる)。空の参加者ID(`/research/participants//dialog-logs`)の要求の応答は、本件では定めない(`(未確認: 実行していない)`)。
- 資格情報は1組の共有のため、誰が取得したかは区別できない。HTTP でのローカル起動では、資格情報は暗号化されない(Cloud Run は HTTPS)。

### スコープ外

- 管理画面、参加者IDの一覧を返す URL、zip・目録・ファイル名の指定、件数の項目。
- 参加者ログインと、参加者の画面・API への認証の追加。
- ダウンロードの記録、研究者ごとのアカウント、本文の匿名化。
- 消えない保存基盤(別 Issue)。
