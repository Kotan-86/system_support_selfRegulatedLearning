# 1人3本の動画の学習 — 研究協力者が、3本の動画を1本ずつ自分で選び、順に学習する(学習3回)

## Issue

#56(https://github.com/Kotan-86/system_support_selfRegulatedLearning/issues/56)。PO の決定 Q0(2026-10-29)により新規に起こした。issue は全体で1つ。実装の PBI ごとに issue を分けるかは未定。関連要件: FR-60、FR-62、FR-63、FR-04、FR-23、NFR-12、NFR-16、NFR-45。関連仕様: [lecture-selection.md](./lecture-selection.md)(#34)、[dialog-log-save.md](./dialog-log-save.md)(#11)、[research-dialog-download.md](./research-dialog-download.md)(#25)、研究用の視聴ログ・小テストの CSV([research-lad-csv-download.md](./research-lad-csv-download.md)(#55、sprint-013。PR #58 で develop に取り込み済み)。下記の前提を参照)。

## 目的(Why)

研究協力者は、1人あたり3本の動画を見て、学習(視聴 → 小テスト → LAD を見ながらの AI 対話 → 対話ログの送信)を3回繰り返す。研究では、同じ協力者が回を重ねたときの振り返りの変化を見るため、1人1本では研究のデータにならない。

現行の設計(#34)は「1人1講義・1回選んだら固定」で、2本目以降を選ぶ手段がなく、2本目の記録・対話は、選択した1本目と異なる講義として 403 で拒否される。そこで、3本を1本ずつ順に選んで学習できるようにし、回ごとに、視聴・小テスト・LAD・AI 対話・対話ログが、その回の動画で一貫するようにする。中断しても同じ ID で続きから再開できるようにし、選び間違いはその回の学習を始める前なら選び直せるようにして、脱落を減らす(プロダクトゴールの「有効なデータ」を増やす)。

## 実現内容(What)

用語:
- **回** = 1本の動画の学習(選択 → 視聴・小テスト → LAD・AI 対話 → 対話ログの送信)。1人の回は **1本目・2本目・3本目** の3回。**回数(3)は固定**(設定にしない。Q11)。
- **回の記録** = その回の学習セッションに紐づく、次のいずれか。(1) 視聴ログ(種類を問わない。準備完了の自動の再生・一時停止は記録されないので、利用者の操作による記録だけになる。Q15、9節)、(2) 小テストの受験、(3) 対話セッション(`/chat` の発言でできたもの、**発言0件の対話ログの保存(ページ離脱・終了ボタン)でできたものを含む**。Q16)。

### 1. 協力者の進行状態

協力者は、常に次のいずれか1つの状態にある。状態は、ログイン ID ごとにサーバーに保存されたデータで決まり、ブラウザ・ログインの有効期限・日付によらない。

| 状態 | 意味 | ログイン後・`/` の移動先 |
|---|---|---|
| **n本目の選択待ち**(n = 1, 2, 3) | n−1 本の回を終えて、n本目をまだ選んでいない(1本目の選択待ち = 何も選んでいない) | 選択の画面 |
| **n本目の学習中** | n本目の講義を選び、その回をまだ終えていない。回の記録がないあいだは、選び直せる(8節) | n本目の講義の画面(`/lecture`) |
| **全体の終了** | 3本目の回を終えた | 全体の終了の画面 |

- 回の順は、選択を確定した順(学習セッションの開始時刻の順)とする。選び直した回は、選び直した時刻を開始時刻とするが、終えた回より後なので、回の順は変わらない。
- ログイン後の移動先に `/reflect` が指定されていたときは、n本目の学習中なら `/reflect`(n本目の振り返り画面)、それ以外の状態では上の表の移動先とする。

### 2. 回の選択(n本目)

- **選択肢**: 講義カタログに登録された講義のうち、**その協力者が終えた回の講義を除いたもの**。カタログの順に、題名と系統を表示する(#34 と同じ)。1本目は6本、2本目は5本、3本目は4本(カタログが6本のとき)。
- 選択の画面と確定の前の確認の画面に、**何本目を選ぶのか**(「n本目 / 3本」)を表示する(Q12)。
- 確定の前の確認は #34 と同じく、題名を示し、もう一度の操作で確定する。ただし、#34 の「一度選ぶと変更できない」の文言は、**「この回の動画を再生する、小テストを受ける、AI と対話する、のいずれかをすると、この回の動画は変えられない」旨**に置き換える(Q4)。文言は PO 確認(AC24)で決める。
- 確定すると、その協力者と講義の学習セッションが1つでき(開始時刻 = 確定の時刻)、状態が「n本目の学習中」になり、講義の画面へ 302 で移る。
- 次のときは、確定を HTTP 400 で拒否し、何も保存しない: カタログにない講義 ID、空の値、講義 ID なし、**その協力者が終えた回の講義**。
- 「n本目の選択待ち」と「選び直せる n本目の学習中」(8節)以外の状態で、選択の画面を開く、または確定を送ったときは、何も保存せず、その状態の移動先(1節の表)へ 302 で移る(2つのタブ・二重送信でも、学習セッションは増えない)。

### 3. 回の終了

- **回の終了** = その回の講義の振り返り画面で、**対話ログを「終了ボタン」(`end_method` が `end_button`)で保存し、成功したこと**(Q1)。ページ離脱による保存(`page_leave`)では、回は終わらない(対話ログは従来どおり保存される)。
- 発言が0件でも、終了ボタンの保存が成功すれば、回は終わる(dialog-log-save.md の Q6 と同じ。Q1)。有効かどうかは、研究データの側で回ごとに判定する(6節)。
- 回の終了は、後の操作(ページ離脱の保存など)で取り消されない。
- 1本目・2本目の回が終わると、状態は「次の回の選択待ち」になる。完了の画面(dialog-log-save.md の完了画面)に、対話ログを送信したことに加えて、**次の動画を選ぶ画面への導線**を表示する。
- 3本目の回が終わると、状態は「全体の終了」になる。完了の画面に、**全体の終了**(3本すべてを終えたこと。以降の操作は不要であること)を表示する。

### 4. 今の回の講義の一貫(FR-62 の回への拡張)

- 「選択した講義」(#34)を、**今の回の講義**(n本目の学習中の講義)に読み替える。#34 の What 4節(画面・API の `lecture_id` の扱い、検査の順序、値の形の規則)は、この読み替えのもとで、そのまま適用する。
  - 参加者の画面と API の講義は、今の回の講義で決まる。`lecture_id` を送らない、または今の回の講義と一致するときは、今の回の講義で処理する。
  - **終えた回の講義**、**選び直しの前の講義**を `lecture_id` に指定したときは、他の不一致と同じく、API は 403、`/reflect?lecture_id=` は 403、`/lecture?lecture_id=` は指定を無視して今の回の講義を表示する。
- **選択待ちの状態**(1本目・2本目・3本目のいずれも)の API は、#34 の「未選択の協力者の API」と同じく HTTP 409 で拒否し、2つの DB のどこにも記録せず、AI を呼ばない。画面(`/`、`/lecture`、`/reflect`)は選択の画面へ 302。
- **全体の終了の状態**の API は、HTTP 409 で拒否し、2つの DB のどこにも記録せず、AI を呼ばない(Q8)。画面(`/`、`/lecture`、`/reflect`、選択の画面)は全体の終了の画面へ 302。
- **終えた回には戻れない**(Q2)。回を終えた直後(次の回の選択待ち・全体の終了)は、上のとおり書き込みの API が 409 になる。次の回の学習中は、終えた回の講義の指定が不一致の 403 になる。いずれも、終えた回の対話の追加・対話ログの保存し直しはできない(dialog-log-save.md の N1・A16 の「再訪で再び対話でき、上書き」は、回の終了の後には適用しない)。**回の途中**の再訪(ページ離脱の保存の後に開き直すなど)は、従来どおり同じ対話セッションに追記できる。

### 5. 回ごとの学習データと AI の文脈

- 回ごとに、学習セッションが1つ、対話セッションが最大1つ、対話ログが最大1件になる(1人あたり、それぞれ最大3つ)。
- LAD・最終更新時刻は、今の回の学習セッションの記録だけを示す。前の回の視聴・小テストを混ぜない。
- AI に渡す内容(講義の文脈・学習データ・対話履歴)は、今の回の講義・学習セッション・対話セッションだけにする。**前の回の講義・記録・対話を混ぜない**(domain-model.md の「AI コンテキストは講義単位(1 LearningSession)」を維持。Q9)。
- 研究者の対話ログのダウンロード(#25)は、1人につき最大3つの対話セッションを、従来の並び(作成時刻の昇順)で返す。JSON の形は変えない(Q7)。

### 6. 有効データと成功の指標(動画単位で判定し、人で数える)

PO の決定(Q6、2026-10-29)による再定義。

- **有効な1回分(人 × 動画)**: 1つの回(学習セッション)について、次をすべて満たす。
  1. その回の動画を1回でも再生した視聴イベントがある(その回の学習セッションに、`action` が `play` の視聴ログが1件以上ある。準備完了の自動の再生は記録されないため、利用者が再生したことを表す。Q15)
  2. その回の講義の小テストを受験している
  3. その回の対話セッションで、AI チューターとの対話が1往復以上ある(根拠は `messages`。対話ログの保存の有無は問わない)
- **有効な1人分**: その協力者の3つの回が、**3つとも有効な1回分**である。
- **主指標: 有効な1人分に達した研究協力者の人数**。最低ライン **10人**(期限 2026年12月末)。満額 30人(募集の上限。現行のまま)。
- 先行指標(日々の確認用。成功の判定には使わない): 回ごとの、選択 → 視聴 → 小テスト → 対話 → 終了 の各段階の通過人数と、3本目の終了(全体の終了)に達した人数。
- データから集計できること(NFR-45 の改訂): 学習セッション(人 × 動画)ごとに上の3条件を判定し、3本とも有効な協力者の人数を数えられる。集計の手段をアプリに作らない(Q13。研究者が DB・既存のダウンロードから判断する)。

### 7. 既存のデータの消去(運用手順)

- 2つの DB のスキーマ(表・列)を変えない(NFR-12、NFR-16。Q3)。進行状態は、既存の表の記録から決める。
- 既存のデータ(P01〜P31)はテスト用だけである(Q5)。本機能のリリースの前に、研究者が、2つの DB(`learning.db`、`tutor.db`)の学習データ・対話データを、本番の複製(#29 の GCS)を含めて消去する(#34 の What 5節と同じ方式)。消去の後は、全員が「1本目の選択待ち」から始まる。
- アプリには、既存のデータを回に移し替える処理、消去する処理を設けない。消去の前のデータ(1人1学習セッション、終了ボタンの後に `end_method` が置き換わった行など)の扱いは定めない。
- 消去の手順は README に書く(改訂対象の一覧)。

### 8. 回の選び直し(FR-63 の改訂。Q4)

- **選び直せる条件**: 協力者が「n本目の学習中」で、**その回の記録(用語の定義)が1件もない**こと。対象は今の回だけで、終えた回は選び直せない。
- **導線**: 選び直せるあいだ、今の回の講義の画面に、選び直しの導線(選択の画面へのリンク)を表示する。選び直せなくなったら表示しない。
- **選択の画面(選び直し)**: 選び直せるあいだ、選択の画面は 200 で開ける。「n本目 / 3本」を表示し、選択肢は、カタログの講義から**終えた回の講義と今の回の講義を除いたもの**(カタログの順)。今の回の講義を変えずに講義の画面へ戻る導線を置く。確定の前の確認は2節と同じ。
- **選び直しの確定**: 選び直せる状態で別の講義 Y を確定すると、今の回の学習セッション(講義 X)がなくなり、Y の学習セッションが1つでき(開始時刻 = 確定の時刻)、状態は「n本目の学習中(Y)」になり、講義の画面へ 302 で移る。協力者の学習セッションの数は n のまま。終えた回の学習セッションと記録は変わらない。
  - 今の回の講義 X を確定として送ったときは、何も変えずに講義の画面へ 302。
  - 終えた回の講義、カタログにない講義 ID、空の値、講義 ID なしは、2節と同じく 400 で、何も変えない。
- **選び直せなくなった後**: 回の記録が1件でもできると、選択の画面を開く・確定を送る操作は、何も変えずに講義の画面へ 302(2節)。
- **記録ができた後の選び間違い**(Q18): 協力者は、その回をそのまま続ける。アプリにも運用にも、記録の後に講義を変える手段を設けず、新しい ID は払い出さない。
- **選択の履歴は残さない**(Q17): 選び直しの前の講義の学習セッションは、2つの DB のどこにも残らない(Q3 のスキーマ不変のため、履歴を置く場所がない)。選び直しの前には回の記録がないため、失われる研究データ(視聴・小テスト・対話)はない。
- **同時の要求**: 選び直しの確定と、その回の最初の記録(視聴ログ・小テスト)が同時に届いたときは、「記録が X の学習セッションに入り、選び直しは成立しない(X のまま)」か「選び直しが成立し、記録は Y に入る、または拒否される」のどちらかになり、`learning.db` に、存在しない学習セッションを指す記録は残らない。選び直しの確定が同時に複数届いたときも、その協力者の学習セッションは n のままになる。
  - `/chat`・対話ログの保存(`tutor.db`)と選び直しが同時に届いたときは、2つの DB にまたがるため、なくなった学習セッションを指す対話セッションが `tutor.db` に残る可能性を、既知の制限とする(制約を参照)。

### 9. 視聴ログの記録: 利用者の操作だけを記録する(Q15。視聴ログの記録の変更、レベル3)

- 講義の画面で、動画の準備完了の処理によって起きる再生・一時停止は、視聴ログに記録しない。講義の画面を開いて準備完了まで進んだだけでは、視聴ログは1件もできない。
- 準備完了の後の、利用者の操作による再生・一時停止・スキップ・シークは、従来どおり、操作1回につき1件記録する(bugs/seek-duplicate-count.md の AC10 の件数を変えない)。
- この変更は、全協力者・全回の講義の画面に適用する(選び直しの有無によらない)。
- 効果: 選び直しの条件(回の記録がない)が、画面を開いただけで失われない(8節)。有効の条件1「1回でも再生」が、画面を開いただけで満たされない(6節)。

## 受入基準

共通: 「2つの DB」は `learning.db` と `tutor.db`。自動テストは、一時ディレクトリの DB、偽の LLM、Flask のテストクライアントで行う。講義 X、Y、Z、W は、カタログの互いに異なる講義(少なくとも1つは lecture-1 以外)。「終了ボタンで保存」は `POST /api/dialog-log` に `end_method: "end_button"` を送り、200 を受けること。「n本目の学習中」などの状態は、What 1節の表の定義による。「回の記録」は What の用語の定義による。「確定」は、確定の前の確認の操作を経て確定の操作を送ること。

### A. 回の進行

1. **1本目の選択**: 学習セッションのない ID でログインすると、選択の画面へ 302 で移る。選択の画面は 200 で、カタログの全講義がカタログの順に並び、「1本目 / 3本」の表示がある。X を確定すると、`learning_sessions` にその ID の行が1つ(講義 X)でき、続く `/lecture` は 200 で X の画面である。〔検証: 自動テスト〕
2. **記録ができた後は、回の途中で選べない**: 1本目の学習中(X)で X の視聴ログを1件記録した後に、選択の画面を開く、または Y の確定を送ると、どちらも `/lecture` へ 302 で、その ID の学習セッションは1つ(X)のまま。〔検証: 自動テスト〕
3. **回の終了は終了ボタンだけ**: 1本目の学習中(X)に、対話ログを `page_leave` で保存しても、続く `/lecture` は X の画面(200)のままで、選択の画面へ移らない。続けて終了ボタンで保存すると、続く `/`・`/lecture`・`/reflect` は、3つとも選択の画面へ 302 で移る。発言0件で終了ボタンで保存したときも同じ。〔検証: 自動テスト〕
4. **回の終了は取り消されない**: AC3 で1本目を終えた後に、本文に `lecture_id` を付けない、または X を付けた `POST /api/dialog-log`(`page_leave`)と `POST /chat` を送ると、どちらも HTTP 409 で、2つの DB の行数と `dialog_logs` の `end_method` は変わらず、AI(偽物)は呼ばれない。続く `/lecture` は選択の画面への 302 のまま。〔検証: 自動テスト〕
5. **2本目の選択肢**: 1本目(X)を終えた後の選択の画面は 200 で、カタログの講義から X を除いたものが、カタログの順に並び、「2本目 / 3本」の表示がある。X は並ばない。〔検証: 自動テスト〕
6. **重複の拒否**: 1本目(X)を終えた後に、X の確定(確定の前の確認の操作を含む)を送ると、HTTP 400 で、学習セッションは増えない。カタログにない講義 ID、空の値、講義 ID なしも、#34 の AC5 と同じく 400 で、何も保存しない。〔検証: 自動テスト〕
7. **2本目の確定**: 1本目(X)を終えた後に Y を確定すると、`/lecture` へ 302 で移り、その ID の学習セッションは2つ(X、Y)になり、続く `/lecture` は 200 で Y の画面である。同じ確定を2回送っても(二重送信)、学習セッションは2つのままで、`/lecture` は Y の画面である。〔検証: 自動テスト〕
8. **3本目と全体の終了**: 2本目(Y)を終えた後の選択の画面には、X と Y を除いた講義が並び、「3本目 / 3本」の表示がある。Z を確定し、Z の回を終了ボタンで終えると、続くログイン後の移動先、`/`、`/lecture`、`/reflect`、選択の画面は、すべて全体の終了の画面へ 302 で移り、全体の終了の画面は 200 である。学習セッションは3つ(X、Y、Z)で、それ以上増えない(全体の終了の後に別の講義の確定を送っても増えない)。〔検証: 自動テスト〕
9. **全体の終了の後の API**: 全体の終了の ID で、#34 の AC14 の6つの API(視聴ログ、小テスト、`/chat`、対話ログ、LAD、最終更新)を、`lecture_id` なし、X・Y・Z のそれぞれを付けて呼ぶと、すべて HTTP 409 で、2つの DB の行数は変わらず、`/chat` では AI(偽物)が呼ばれない。〔検証: 自動テスト〕
10. **選択待ちの API**: 1本目・2本目・3本目の選択待ちのそれぞれで、AC9 と同じ6つの API を `lecture_id` なしで呼ぶと、すべて HTTP 409 で、2つの DB の行数は変わらない。未ログインの 401、他人の `participant_id` の 403 は、#30 のとおり変わらない(409 にならない)。〔検証: 自動テスト〕

### B. 回の選び直し

11. **選び直しの導線と画面**: 1本目の学習中(X)で回の記録がないとき、`/lecture` は 200 で X の画面であり、選び直しの導線(選択の画面へのリンク)を含む。選択の画面は 200 で、「1本目 / 3本」の表示があり、カタログの講義から X を除いたものがカタログの順に並ぶ。2本目の学習中(Y。1本目は X で終了)で記録がないときは、「2本目 / 3本」で、X と Y を除いた講義が並ぶ。〔検証: 自動テスト〕
12. **選び直しの確定**: (a) 1本目の学習中(X、記録なし)に Y を確定すると、`/lecture` へ 302 で、その ID の `learning_sessions` の行は Y の1つだけ(X の行はない)になり、続く `/lecture` は 200 で Y の画面である。続けて `lecture_id` を付けない視聴ログを送ると、Y の学習セッションに入る。(b) 1本目(X)を終え、2本目の学習中(Y、記録なし)に Z を確定すると、行は X と Z の2つになり、X の行と、X の学習セッション・対話セッションに紐づく2つの DB の行(視聴ログ、小テスト、対話セッション、発言、対話ログ)の値は確定の前と同じである。(c) (b) の状態で X(終えた回の講義)の確定を送ると 400、今の回の講義 Z の確定を送ると何も変えずに `/lecture` へ 302 で、どちらも行は変わらない。〔検証: 自動テスト〕
13. **記録ができたら選び直せない**: 1本目の学習中(X)で、次の (a)〜(d) のそれぞれを1回だけ行った後に、`/lecture` は選び直しの導線を含まず、選択の画面は `/lecture` へ 302、Y の確定は `/lecture` へ 302 で、2つの DB の行数は変わらず、続く `/lecture` は X の画面である: (a) 視聴ログを1件送る、(b) 小テストを1回送る、(c) `/chat` で1回発言する、(d) 発言0件で対話ログを `page_leave` で保存する。(a) は `play`、`pause`、`forward_skip`、`forward_seek` のそれぞれで別に行い、どの種類でも同じ結果になる。〔検証: 自動テスト〕
14. **選び直しの同時の要求**: 1本目の学習中(X、記録なし)に、(a) Y の確定と W の確定を同時に送ると、終了後のその ID の学習セッションは1つで、講義は Y か W のいずれかである。(b) Y の確定と、`lecture_id` を付けない視聴ログを同時に送ると、終了後、`viewing_logs` のすべての行の学習セッション ID が `learning_sessions` に存在し、その ID の学習セッションは1つである。(a)・(b) を、それぞれ複数回くり返しても成り立つ。〔検証: 自動テスト(同時の要求を並べる。どちらが先に成立するかは問わない)〕
15. **確定の前の確認の表示**: n本目(n = 1, 2)の確定の前の確認の応答に、選んだ講義の題名と、「n本目 / 3本」と、「再生」「小テスト」「対話」の語を含む「この回の動画が変えられなくなる条件」の文言が含まれ、#34 の「一度選ぶと変更できない」の文言は含まれない。この時点では選択は保存されない。〔検証: 自動テスト〕
16. **画面を開いただけでは記録にならない**(Q15): 講義の画面のスクリプトを、YouTube API の代役(状態の変化を即時に通知する)で読み込み、準備完了まで進めたとき、視聴ログは1件も送られない(記録を捨てずに数える)。続けて利用者の再生の操作をすると `play` が1件、一時停止の操作をすると `pause` が1件送られる。〔検証: 自動テスト(Node の代役。bugs/seek-duplicate-count.md の AC10 と同じ方式。Node が無い環境ではスキップし、品質報告で実行されたこと(`PASSED`)を確認する)〕

### C. 中断と再開

19. **終えた回・選び直しの前の講義の指定は拒否**: 2本目の学習中(Y。1本目は X)に、AC9 の6つの API に `lecture_id` を X にして呼ぶと、すべて HTTP 403 で、2つの DB の行数は変わらず、`/chat` では AI(偽物)が呼ばれない。`/reflect?lecture_id=X` は 403、`/lecture?lecture_id=X` は 200 で Y の画面である。1本目の学習中に X から Y へ選び直した後に、`lecture_id` を X にした6つの API も、同じく 403 である。〔検証: 自動テスト〕
20. **AI の文脈は今の回だけ**: 1本目(X)で発言を送って終えた後、2本目の学習中(Y)に `/chat` を送ると、対話セッションは Y の学習セッションに紐づく新しいもの(1本目の対話セッションと異なる)になり、AI(偽物)に渡す内容に、Y の講義の文脈(字幕または講義情報)が含まれ、X の講義の文脈と、1本目の発言の本文が含まれない。〔検証: 自動テスト(講義ごとに区別できる文字列で判定)〕
21. **対話ログは回ごと**: 3本の回をそれぞれ1往復以上の発言のあとに終了ボタンで終えると、その ID の対話ログは3件で、各対話ログの講義 ID と学習セッション ID は、それぞれの回の講義・学習セッションと一致し、各対話ログの発言は、その回の発言だけを含む。研究者の参加者別のダウンロードに、その ID の対話セッションが3つ、作成時刻の昇順(X、Y、Z の順)で入り、JSON の形(キー、`format_version`)は、この機能の前と同じである。〔検証: 自動テスト〕
22. **協力者ごとの独立**: ID `A` と `B` が、それぞれ異なる回(例: `A` は2本目の学習中、`B` は1本目の学習中で記録なし)にあるとき、互いの状態・選択肢・記録に影響しない。`B` の選び直しは `A` の学習セッションを変えない。同じ講義を、異なる ID が同じ回、異なる回で選べる。〔検証: 自動テスト〕

### E. スキーマ

23. **スキーマを変えない**: この機能の後に、2つの DB の表と列の定義(`sqlite_master` の内容)が、この機能の前と同じである。〔検証: 自動テスト〕

### F. 画面(PO 確認)

24. **通しの操作**: ブラウザで、1つの ID により、1本目を選ぶ(「1本目 / 3本」の表示、6本の選択肢、確定の前の確認と、変えられなくなる条件の文言)→ 講義の画面に選び直しの導線がある → 導線から別の講義に選び直す → 選び直した講義の画面を開いただけ(再生しない)では導線が残る → 再生すると(再読み込みの後)導線が消える → 小テスト → 振り返り画面で AI と対話 → 終了ボタン → 完了画面に「次の動画を選ぶ」導線 → 2本目の選択の画面(1本目の講義が並ばない)→ … → 3本目の終了ボタン → 全体の終了の表示、の順に操作できる。途中(2本目の学習中)でブラウザを閉じ、別の日時に相当する再ログインで、2本目の講義の画面から続けられる。どの回でも、画面・LAD・AI の応答の文脈が、その回の講義になる。確定の前の確認と全体の終了の画面の文言を、PO が確認する。〔検証: PO確認〕

### G. 回帰とドキュメント

25. **回帰**: 1本目の学習中の協力者の操作(#34 の AC10〜15・17 の内容。「選択した講義」を「今の回の講義」と読む)、#30 のアクセス制御、#25 の研究者のダウンロード、dialog-log-save.md の回の途中の保存・再訪(終了ボタンの前)、視聴ログの記録(準備完了の後の利用者の再生・一時停止・スキップ・シーク。bugs/seek-duplicate-count.md の AC10、#34 の講義 ID の付与)は、この機能の前と同じ結果になる。既存の自動テスト(`uv run pytest tests/ -v`、実 LLM を除く)は、本仕様で置き換えた AC を検査するもの(制約の「書き換え」)を本仕様に合わせた上で、すべて成功する。〔検証: 自動テスト〕
26. **ドキュメント**: 下記「改訂対象の一覧」の各ドキュメントが、PO の決定どおりに改訂され、「1人1講義」「1回選んだら固定(1人1本)」「一度選ぶと変更できない」「選び間違いは新しい ID の払い出し」「再訪で上書き(回の終了後)」「有効な1人分 = 1本の視聴・小テスト・対話」「講義の画面を開くと(準備完了で)視聴ログが記録される」を現行の挙動・定義として説明する記述が残っていない。README に、既存のデータの消去の手順(What 7節)、選び直しの条件、記録ができた後の選び間違いは、その回をそのまま続ける(新しい ID を払い出さない)ことがある。〔検証: AI実行〕

## 制約・関連機能

- 関連: [lecture-selection.md](./lecture-selection.md)(#34。本仕様は「選択した講義」を「今の回の講義」に一般化する)、[dialog-log-save.md](./dialog-log-save.md)(終了ボタン・完了画面・再訪)、[participant-login.md](./participant-login.md)(ログイン後の移動先)、[domain-model.md](./domain-model.md)、[research-dialog-download.md](./research-dialog-download.md)、[research-lad-csv-download.md](./research-lad-csv-download.md)(#55 の CSV の仕様)、[bugs/seek-duplicate-count.md](./bugs/seek-duplicate-count.md)(視聴ログの記録)。
- **スキーマの制約(NFR-12、NFR-16。Q3)**: 2つの DB の表・列を変えない。回の順序は学習セッションの開始時刻(確定の時刻)、回の終了は対話ログの記録(その回の対話セッションの `end_method` が `end_button`)、選び直しは記録のない学習セッションの行の削除で表す。
- **回の終了の記録の安定性**: 前提のとおり、`dialog_logs` は後の保存で `end_method` が置き換わる。本仕様では、回の終了の後、その回の対話・対話ログの保存を受け付けない(What 4節、AC4)ため、終了ボタンの記録は以後置き換わらない。既存のデータは消去する(What 7節)ため、置き換わった行は残らない。
- **2つの DB にまたがる判定**: 進行状態と選び直しの可否は、`learning.db`(学習セッション、視聴ログ、小テスト)と `tutor.db`(対話セッション、対話ログ)の両方を読んで決まる。参加者の画面・API の要求ごとに、この判定が1回以上入る。
- **選び直しの排他(既知の制限)**: `learning.db` の中の「記録がないことの確認」と「学習セッションの置き換え」は、同時の視聴ログ・小テスト・選び直しの確定に対して、一方だけが成立するようにする(AC14)。`tutor.db` の対話セッションの作成と選び直しが同時に起きたときは、2つの DB を1つの処理で守れないため、なくなった学習セッションを指す対話セッション(発言0〜数件)が `tutor.db` に残る可能性がある。そのような対話セッションは、進行状態の判定に使わない(判定は学習セッションから辿る)。#25 のダウンロードには出うる。協力者が別のタブで振り返り画面と選び直しを同時に操作したときだけ起きる。
- **共有IF**(実装の PBI の最初に固定する):
  - 「ログインした協力者の進行状態」(状態の種類、n、今の回の講義、終えた回の講義の一覧、選び直せるか)を、画面・API の各ルートへ渡す方法(#34 の「選択した講義」を置き換える)。
  - 「何本目」の定義(学習セッションの開始時刻の昇順。同じなら ID の昇順)。PBI-A と PBI-C で同じ定義を使う。
  - 全体の終了の画面の URL。選択待ち・全体の終了の API の 409 の応答の本文(既存の `lecture_not_selected` と区別するかを含む)。
  - 完了画面の「次の動画を選ぶ」導線と全体の終了の表示を、対話ログの保存の応答で画面に伝える方法。
  - 選び直しの確定の送り先(既存の確定の送り先を使うか、別にするか)。
- CSRF: #34 と同じ(`SameSite=Lax`、トークンなし)。
- **リリースの条件**: PBI-A・PBI-B(PBI-D に分けたときは PBI-D も)の完了と、既存のデータの消去(What 7節)の後に、本番の協力者に使わせる(PBI-A だけでは、完了画面の導線と選び直しがない)。
