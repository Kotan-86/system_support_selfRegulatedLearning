# 字幕の整形 — 講義ごとに整形済みの表示用字幕を用意し、意味の伝わる1文の単位で、フィラーを除いて表示する

## Issue

#44

## 目的(Why)

講義ページの字幕(#36)は、YouTube の自動字幕の SRT をキューの単位でそのまま表示している。キューは語や言い回しの途中で切れ(例: 「つまり公式としてこれを証明するだけで/なく直感的に…」「この3/つについて」)、lecture-1 では隣り合うキューの時刻が重なるため、断片が 2〜3 秒ごとに切り替わる。学習者は断片をつなぎ直しながら読むことになり、字幕が理解の助けにならない。また「え」「まあ」などのフィラーが、文の中に読点なしで混ざり(例: 「思いますえこれは」)、読みにくさを増している。

表示する字幕を、1文として意味が伝わる単位にまとめ、フィラーを除くことで、字幕を読むだけで講義の内容を追えるようにする。SRT に句読点がなく、文字の規則だけでは語の途中で切らないことを保証できない(前提を参照)ため、整形は実行時の規則ではなく、講義ごとに整形済みの表示用字幕を用意し、PO が全文を確認する(#35 と同じ進め方)。保存している SRT と、AI チューターが使う字幕は変えない(研究データと LLM の文脈を変えないため)。

### POの意図(確認済み)

- 整形の対象は、表示用の字幕だけ。保存するデータ(SRT)と、AI チューターの文脈(`parse_srt_file` / `get_segments_for_times` の結果)は変えない。〔出典: issue #44 の PO 追記(2026-10-26)、および本起草の依頼(2026-10-26)〕
- 課題の例: 語や言い回しの途中で字幕が切れる(「音声/と音韻」「この3/つについて」)。隣り合う字幕の時間が重なる。〔出典: issue #44 の PO 追記(2026-10-26)〕
- **Q1 方式**: (c) 講義ごとに、整形済みの表示用字幕を別ファイルで用意する。案は AI が作り、PO が全文を確認する(#35 と同じ進め方)。SRT 本体は変えない。整形済みファイルは表示専用で、`parse_srt_file` による AI チューターの文脈、保存データには使わない。〔出典: PO 決定(2026-10-26。本仕様の Q1)〕
- **Q2 1件の長さ**: 40 字前後。超えたら意味の切れ目(「〜が」「〜ので」など)で分ける。半角空白(「半径 r の円」など)は残す。〔出典: PO 決定(2026-10-26。本仕様の Q2。SM 仮置き)〕
- **Q3 時刻**: 開始 = その文の最初の文字を含む元キューの開始。終了 = 次の文の開始(最後の文と、元に隙間がある箇所は、元の終了)。文の境目が元キューの途中なら、文字数の比で時刻を分ける。〔出典: PO 決定(2026-10-26。本仕様の Q3)〕
- **Q4 フィラー**: 除く =「えっと」「えー」、単独の「え」、「うーん」「あのー」、単独の「ま」「まあ」。残す =「その」「はい」。「ええ」は文脈を見て判断する(判断は整形済みファイルの作成時に行い、PO が確認する)。「答え」「まず」「たまたま」などの語中の文字は除かない。〔出典: PO 決定(2026-10-26。本仕様の Q4)〕
- **Q5 括弧のキュー**: `[音楽]`、`[笑い]` などは、1件として残す。〔出典: PO 決定(2026-10-26。本仕様の Q5。SM 仮置き)〕
- **Q6 整形済みファイルがない講義**: 元の SRT を #36 の規則で表示する。〔出典: PO 決定(2026-10-26。本仕様の Q6)〕
- **Q7 大きさの基準**: 整形済みのデータは、PBI の大きさの基準(src 300 行)に数えない(データ扱い)。〔出典: PO 決定(2026-10-26。本仕様の Q7。SM 仮置き)〕

## 実現内容(What)

### 用語

- **元の SRT**: `lectures/<講義ID>/subtitles.srt`。
- **整形済みファイル**: `lectures/<講義ID>/subtitles.display.srt`(提案。下の「整形済みファイルの置き場所・名前・形式」)。表示専用。
- **除去一覧**: `lectures/<講義ID>/display-fillers.md`(提案)。整形済みファイルを作るときに除いたフィラーの一覧。
- **件**: 整形済みファイルの1ブロック(表示される字幕の1件)。

### 振る舞い

1. **表示する字幕**: 講義ページを開いたとき、その講義の整形済みファイルがあれば、字幕の表示領域には整形済みファイルの各件を、その時刻で表示する。字幕の表示・非表示の切替、再生位置への同期、記録しないこと(#36 の AC1〜9、12〜14)は変えない。
2. **整形済みファイルがない講義**: 元の SRT を、#36 の規則(有効なキューのうち開始が最も遅い1件)で表示する。SRT もなければ、表示領域は空(#36 の AC12)。
3. **元のデータを変えない**: 元の SRT と、AI チューターに渡る字幕の文は変えない。AI チューターの文脈は、整形済みファイルを読まない。
4. **整形済みファイルの内容**(作成の規則。AI が案を作り、PO が全文を確認する):
   - 元の SRT のキューの文を、時刻の順につなげ、1文として意味が伝わる単位に区切り直す。1件は 40 字前後とし、超えるときは意味の切れ目(「〜が」「〜ので」など)で分ける。語や言い回しの途中では区切らない。
   - フィラー(Q4 の「除く」)だけを除く。「その」「はい」は残す。「ええ」は文脈で判断し、除いたときは除去一覧に理由を書く。フィラー以外の文字は、追加も変更も削除もしない(半角空白を含む。誤認識の修正は #35 の担当)。
   - `[音楽]`、`[笑い]` などの括弧のキューは、それだけで1件にする。
   - 時刻は、Q3 の規則で付ける(定義は AC5)。
5. **進め方**: 整形済みファイルと除去一覧は、講義ごとに AI が案を作り、PO が全文を確認して承認する。承認された版だけをリポジトリに入れる。元の SRT が #35 などで変わったときは、その講義の整形済みファイルを作り直す。

### 整形済みファイルの置き場所・名前・形式(提案)

| 項目 | 提案 | 理由 |
|---|---|---|
| 置き場所・名前 | `lectures/<講義ID>/subtitles.display.srt` | 講義のアセットと同じ場所で、講義 ID から一意に決まる。#35 の `subtitles.proofread.srt` と同じ命名。SRT の構造テストはファイル名で対象を指定しているので、検査の対象が変わらない(前提) |
| 形式 | 元の SRT と同じ形式: UTF-8(BOM なし)、改行は CRLF、番号は 1 からの連番、時刻の行は `HH:MM:SS,mmm --> HH:MM:SS,mmm`、1ブロック = 番号・時刻・1行の文 | 既存の SRT の読み込みで、文を変えずに読める(前提。実行で確認)。PO が全文をテキストとして読める。動画プレイヤーに読ませて確認することもできる。#35 の構造の検査の考え方を流用できる |
| 除去一覧 | `lectures/<講義ID>/display-fillers.md`。表の列: 元の番号 / 位置(その元キューの文の中の、0 から数えた文字の位置) / 除いた語 / メモ(「ええ」の判断の理由など) | PO が除いた語を一覧で確認できる(#35 の `proofread-diff.md` に相当)。自動テストが、整形済みファイルの各文字を元の文字に対応づけ、文字の保存(AC2)と時刻の規則(AC5)を厳密に検査できる |

## 受入基準

用語は「実現内容」の定義による。AC1〜10 は、整形済みファイルがある講義について検査し、ないときはその講義についてスキップする(#35 の Q4 と同じ。ただし AC18 の承認後は、承認された講義のファイルがあることを AC1 で必須にする)。AC5 は、未解決の論点 Q8 の回答に従う(推奨で書いた)。AC7 の上限は Q9 の回答に従う(推奨で書いた)。

### 整形済みファイルの構造と内容(自動テストで確かめる範囲)

1. **ファイルの形式**: 整形済みファイルは、UTF-8(BOM なし)、改行は CRLF のみで、番号は 1 からの連番で欠番がなく、全ブロックが「番号・時刻(`HH:MM:SS,mmm --> HH:MM:SS,mmm`)・1行の文」の3行で、文が空の件がない。既存の SRT の読み込みで読め、件数がブロック数と一致する。PO が承認した講義(AC18)では、ファイルが存在する。〔検証: 自動テスト〕
2. **元の文字の保存(フィラー以外は欠けない、足さない)**: 講義ごとに、整形済みファイルの各件の文を時刻の順につなげた文字列は、元の SRT の各キューの文を時刻の順につなげた文字列から、除去一覧の各行(元の番号・位置・除いた語)が指す文字だけを除いたものと、半角空白を含めて完全に一致する(各行の先頭・末尾の空白は数えない)。除去一覧の各行の「除いた語」は、元の番号のキューの文のその位置に実在し、「えっと」「えー」「え」「うーん」「あのー」「ま」「まあ」「ええ」のどれかである。「その」「はい」は除去一覧に現れない。〔検証: 自動テスト〕
3. **時刻の順序と重なり**: 各件は開始時刻の順に並び、どの件も 開始 < 終了 で、前の件の終了 <= 次の件の開始である。〔検証: 自動テスト〕
4. **時刻の範囲**: 最初の件の開始は、元の SRT の最初のキューの開始と同じ。最後の件の終了は、元の SRT の最後のキューの終了と同じ。〔検証: 自動テスト〕
5. **時刻の規則(Q3)**: AC2 の対応づけで、各件の最初の文字と最後の文字が、どの元キューの何文字目かを決めたとき、各件の時刻が次の値と ±0.01 秒以内で一致する。〔検証: 自動テスト〕
   - 開始: 最初の文字が元キューの先頭の文字なら、その元キューの開始。先頭でない(文の境目が元キューの途中)なら、元キューの開始 + 元キューの長さ ×(元キューの文のうち、その文字より前の文字数 ÷ 元キューの文の文字数)。文字数は、元キューの文の文字数(フィラーと半角空白を含む)で数える(Q8-2 の推奨)。元キューの長さは、元キューの開始から、元キューの終了と次の元キューの開始の早い方まで(Q8-1 の推奨。lecture-2・3 では元キューの終了と同じ)。
   - 終了: 次の件の開始。ただし、最後の件は、元の SRT の最後のキューの終了。件の最後の文字を含む元キューが、その元キューの最後の文字で終わり、次の元キューとの間に隙間がある(元キューの終了 < 次の元キューの開始)ときは、その元キューの終了。
6. **括弧のキューを1件として残す**: 元の SRT の括弧のキュー(lecture-1: `[音楽]` ×3、lecture-2: `[音楽]` ×1、lecture-3: `[笑い]` ×1、`[音楽]` ×1)が、それぞれ、文がそれだけの1件として、整形済みファイルにある。括弧のキューの文が、ほかの文とつながった件はない。〔検証: 自動テスト〕
7. **1件の長さの上限**: 括弧のキューを除き、どの件も、文の文字数(半角空白を含む)が 50 字以下である(Q9 の推奨。目安は 40 字前後)。〔検証: 自動テスト〕
8. **語の途中で区切らない(固定の例)**: 次の各文字列が、整形済みファイルのどれか1件の文の中に、途中で区切られずに含まれる。〔検証: 自動テスト〕
   - lecture-1: 「皆さんの多くは学校で球の表面積が4πr²であることを学んだでしょう」(元のキュー2〜4)、「証明するだけでなく」(元のキュー9〜10の境目)
   - lecture-2: 「この問題は割と有名なんですね」、「知ってる人も多いと思うんですが」(元のキュー5〜6の境目)
   - lecture-3: 「すごくね有名なパラドックスなんですけど」、「3人の死刑囚」(元のキュー5〜6の境目)
9. **フィラーの除去(固定の例)**: 整形済みファイルの文を時刻の順につなげた文字列に、左の文字列が含まれず、右の文字列が含まれる。〔検証: 自動テスト〕

### 整形済みファイルの作成と承認(AI実行・PO確認)

17. **PO の確認の前に自動の検査を通す**: 講義ごとに、整形済みファイルと除去一覧の案を PO に提示する時点で、その講義について AC1〜10 の自動テストが成功し、元の SRT に差分がない(`git diff --exit-code -- lectures/<講義ID>/subtitles.srt` が 0)。〔検証: AI実行〕

    - 各件が、1文として意味が伝わる単位である(前後の件を読まなくても、何を言っているかが分かる)。

    - 40 字を大きく超える件がなく、分けた箇所が意味の切れ目(「〜が」「〜ので」など)である。
    - 除くべきフィラー(Q4 の「除く」)が、件の文に残っていない。
    - 除去一覧の各行が、フィラーとして除いてよいものである(とくに「ええ」の判断と、単独の「え」「ま」の判断)。
